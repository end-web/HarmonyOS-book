# 下载可靠性修复设计

## 状态

本设计于 2026-07-14 经用户确认。它延续现有长期下载架构，对当前未提交改动和既有下载链路做定点修复，不引入新的数据库、系统下载管理器或大规模分层重构。

## 背景

当前下载实现已经具备流式写盘、长期文件存储、暂停恢复、进程重启恢复、下载管理页、实时进度和通知栏能力。现有改动还修复了分块写入时错误使用 `offset: 0` 导致反复覆盖文件头的问题，并增加了落盘大小校验。

完整走查发现以下未闭环问题：

- 新增恢复代码存在 `common.Context` 与 `common.UIAbilityContext` 类型不匹配，阻断 ArkTS 编译。
- 连载目录头部插入章节后，按下标生成的章节 ID 会变化；当前 URL 匹配失败后无条件按 ID 兜底，可能复用、播放或删除错误章节。
- 文件发布回退误把任意 `moveFile` 异常当作同名文件冲突，失败路径可能删除旧最终文件和新临时文件。
- 恢复出的书籍变量没有传入音频规则解析上下文。
- 最后一章完成与暂停并发时，整本记录可能永久停在 `paused`。
- 文件探测没有按错误码区分“文件不存在”和临时 I/O 失败，可能保留伪完成状态。
- 响应校验过度信任 `audio/*` MIME，且只保存首个网络分块作为文件头。
- 同一本书的并发时长补齐可能吞掉后一次请求。
- 播放器为增加详情入口移除了唯一的播放模式切换入口。
- 章节列表通过把刷新计数拼进 key 强制重建，key 不稳定。

## 目标

- 恢复 default HAP 编译。
- 保证下载记录、章节 UI 和离线播放始终指向同一稳定章节。
- 保证暂停、恢复、删除、清空和进程重启后的状态可收敛。
- 保证最终文件发布失败时不会主动破坏已有最终文件。
- 保证依赖书籍变量的规则在冷启动恢复后与前台解析一致。
- 拒绝明显无效或未知格式的离线音频响应。
- 保留播放器的播放模式和书籍详情两个入口。
- 为可纯化的决策补充本地单元测试，并用 DevEco Hvigor 完成真实构建。

## 非目标

- 不实现 HTTP Range 断点续传；暂停或失败的未完成章节仍从头下载。
- 不支持 HLS 播放列表和分片离线化。
- 不改用系统下载管理器。
- 不改变“允许任意网络类型下载”的既定产品策略。
- 不清理与本次下载可靠性无关的全仓库 ArkTS warning。

## 方案选择

采用现有架构内的定点修复：继续由 `DownloadService` 管理队列和任务代际，`DownloadStore` 管理持久状态，`AudioDownloadTransport` 管理单文件传输，`DownloadPolicy` 承载可测试的纯判断。

没有选择完整状态机/Repository 重构，因为会扩大当前未提交改动的回归面；没有选择系统下载管理器，因为现有书源依赖动态规则、自定义 Header、Cookie、WebView 嗅探和临时签名 URL。

## 详细设计

### 1. 上下文类型

`DownloadService` 的上下文字段、`init()` 和 `setContext()` 统一使用 `common.UIAbilityContext`。实际注入点始终是 `EntryAbility.context`，而后台长时任务、通知 WantAgent 和 `DataService.getBookById()` 都需要 UIAbility 级上下文。`DownloadStore` 继续只依赖其父类型 `common.Context`。

### 2. 稳定章节身份

在线章节以非空 `pageUrl` 为权威身份。统一匹配规则如下：

1. 目标和记录都有 `pageUrl` 时，只允许 URL 完全相等，禁止再按章节 ID 兜底。
2. 仅当一方缺少 `pageUrl`，为兼容旧记录才允许按章节 ID 匹配。
3. URL 相同但生成 ID、标题或下标变化时，复用文件并刷新记录元数据。
4. 单章删除必须同时传入章节 ID 和稳定 URL；队列取消、记录查找和文件查找使用同一规则。

该规则放入 `DownloadPolicy` 的纯函数，并由 `DownloadStore`、`DownloadService` 和页面调用方共同使用。它避免新 `c0` 误命中旧 `c0`，同时兼容早期缺少稳定 URL 的记录。

### 3. 文件写入与发布

保留串行 `writeChain`，写入时不提供 `offset`，让 SDK 从当前文件指针继续写。文件发布流程调整为：

1. 下载前删除同路径的旧 `.part` 和历史 `.swap`。
2. 完成写入后执行 `fsync`、关闭文件，并校验内存累计字节、`.part` 实际大小和 `Content-Length`。
3. 使用 `fileIo.moveFile(partPath, finalPath, 0)` 一次性覆盖发布。
4. 发布失败直接向上抛出，保留原有最终文件的 SDK 语义，不再执行删旧后重试。
5. 失败或取消只清理 `.part`；删除书籍、单章和全部下载时额外清理历史 `.swap`。

对于无 `Content-Length` 的响应，每累计固定字节量重新检查剩余空间，始终保留安全余量，避免未知长度响应持续写满磁盘。

### 4. 音频响应验证

传输层累计最多 64 字节的响应前缀，而不是只复制第一个网络分块。`DownloadPolicy` 扩充常见本地可播放容器签名，包括 MP3/ADTS、FLAC、Ogg、WAV、AIFF、MP4/M4A、AMR、ASF 和 APE。

验证顺序：

1. URL 或 MIME 为 HLS 时拒绝。
2. MIME 明确为非音频/非受支持二进制容器时拒绝。
3. 前缀为 HTML、XML、JSON 或纯文本错误页时，无论 MIME 如何都拒绝。
4. 文件必须命中受支持音频签名；不能只因服务端声明 `audio/*` 就接受未知内容。
5. 字节数和最小文件大小仍必须通过。

### 5. 书源变量透传

`BookSourceService.getAudioUrl()` 和 `resolveAudioRequest()` 增加可选 `variables` 参数。普通书源解析章节 URL、创建 `AnalyzeContext`、配置 JavaBridge/source context、解析最终音频 URL 及其请求 Header 时都传入同一份变量。

前台播放和下载队列都传入对应的 `book.variables`；冷启动恢复使用补回变量后的 `item.book.variables`。内置书源继续使用现有 dispatcher，不受该可选参数影响。

### 6. 暂停、恢复与启动归一化

书籍状态继续由章节记录推导，显式暂停只在确实存在未完成章节时成立：

- `pauseBook()` 先使旧任务代际失效并取消传输，再把活动章节归为 `pending`。
- 若仍有 `pending/resolving/downloading` 章节，书籍状态为 `paused`。
- 若没有未完成章节，则重新计算为 `completed`、`failed` 或 `idle`，不得强行写成 `paused`。
- `resumeBook()` 没有可入队章节时也要重新计算并保存状态，而不是直接返回。
- 冷启动只在“原状态为 paused 且归一化后仍有未完成章节”时保留暂停。

任务代际检查继续在每个异步边界后执行，暂停不记录为失败，删除优先于保留已发布文件。

### 7. 文件探测

文件有效性探测只执行一次 `statSync`，并检查 `BusinessError.code`：

- `13900002` 返回 `missing`。
- 可读但过小返回 `too_small`。
- 与已知记录字节数不同返回 `size_mismatch`。
- 其他 I/O、权限或临时错误返回 `stat_error`。

启动归一化仅对明确的 missing、too_small、size_mismatch 降级并清理；stat_error 暂时保留记录。运行时 `getDownloadedFilePath()` 仍只接受明确的 `ok`，避免把不可访问文件交给播放器。

### 8. 时长补齐

保留按书籍串行补齐，增加“再次运行”标记：已有任务运行时收到新的补齐请求，不直接丢弃，而是标记该书需要重跑。当前遍历结束后若标记存在，再执行一轮，直到没有新请求。

每次只处理状态为 completed、文件有效且 durationSec 缺失的章节。删除或清空期间记录已从 Store 移除时，不重新插入旧记录。

### 9. ArkUI 与播放器入口

- 恢复 `PlayMode` 导入、循环切换方法和播放器底部左侧播放模式图标。
- 恢复顶部右侧书籍详情图标，详情页继续承载整本下载入口。
- 章节列表 key 优先使用 `originSourceValue` 或网络页面 URL，缺失时才回退章节 ID；下载状态变化通过数据源通知或显式状态参数刷新，不把 tick 拼入 key。
- 保持现有 V2 状态装饰器和成对 emitter 注册/释放，不在 `build()` 中执行下载或持久化副作用。

## 数据流

1. 页面把 Book 和目标章节交给 `DownloadService`。
2. Service 使用稳定 URL 查重并创建带任务代际的队列项。
3. 解析阶段把 Book variables 传给 `BookSourceService`，得到最终 URL 和 Header。
4. Transport 流式写入 `.part`，持续上报进度并检查空间。
5. Transport 完整验证后一次移动为最终文件。
6. Service 再次校验任务代际，写 completed；若此时仅发生暂停，恢复时可认领已发布文件；若发生删除则清理文件。
7. Store 持久化后发送下载事件，页面和通知读取同一记录快照。

## 兼容与迁移

- 不改变下载 JSON 的字段结构，旧记录可直接读取。
- 旧记录有 pageUrl 时立即采用严格 URL 身份；没有 pageUrl 时保留 ID 兼容路径。
- 已完成记录继续保存绝对 filePath，因此文件路径算法无需迁移。
- 历史 `.swap` 作为遗留临时文件在下一次同章下载或删除操作中清理。

## 测试设计

本地 Hypium 重点覆盖纯策略：

- 同 URL、不同 ID 能匹配；同 ID、不同非空 URL 不能匹配；缺 URL 的旧记录允许 ID 兼容。
- HTML/JSON 即使声明 audio MIME 也被拒绝。
- 分片前缀累积后能识别跨首块的音频签名。
- 常见音频签名和未知签名分类。
- 暂停仅在存在未完成章节时保留；全部完成时收敛为 completed。
- 目标 SDK 文件错误码对 missing/stat_error 的分类。
- 下载失败原因继续稳定映射。

构建与设备验证：

- 使用 DevEco Studio 自带 Hvigor 构建 default HAP，最多循环修复 5 次编译错误。
- 下载两个并发章节，验证文件大小、内容头和离线播放。
- 最后一章完成时立即暂停，确认不会卡在 paused。
- 下载中暂停、删除、清空和强杀进程，重启后验证状态和临时文件。
- 模拟目录头部插入新章节，确认不会复用或删除旧章节音频。
- 验证依赖 `book.variables` 的书源在冷启动恢复后可解析。
- 验证无 Content-Length、伪 audio MIME、空间不足和网络中断路径。
- 验证播放模式切换和顶部详情入口同时可用。

## 验收标准

- default HAP 编译成功，新增下载策略测试通过。
- 目录重排后不出现错章、错播或误删。
- 任意文件发布错误都不会主动删除已有最终文件。
- 冷启动恢复能使用书籍变量解析音频请求。
- 100% 完成记录不会停留在 paused。
- 缺失或损坏文件不会继续作为可播放完成文件。
- 错误页和未知格式不会被保存为 completed。
- 并发完成的章节最终都能补齐可解析时长。
- 播放模式和书籍详情两个入口均保留。
