# 下载管理页与书架删除联动设计

## 目标

新增集中下载管理页面，避免用户必须进入每本书详情查看下载状态；同时保证任何书籍移出书架时，
对应长期离线下载任务和文件都会被清理，不留下孤立下载数据。

## 下载管理页

新增 `DownloadManagerPage`，从“我的”页面进入，并注册到现有 Navigation 路由。

页面直接读取 `DownloadStore` 中的书籍下载记录，监听 `EVT_DOWNLOAD_UPDATED` 实时刷新。每条记录展示：

- 封面、书名和作者。
- 已下载章节数、总章节数和失败章节数。
- 已完成文件总大小。
- 下载中、暂停、完成、失败等状态。
- 暂停、继续、失败重试和删除下载操作。

点击书籍主体进入详情页。删除操作需要二次确认。页面顶部显示全部长期下载文件总占用空间；没有记录时显示空状态。

页面不引入新的数据库或状态管理层，继续以 `DownloadStore` 为唯一下载记录来源。

## 服务接口

`DownloadService` 增加适合管理页使用的只读列表及重试入口：

- 获取全部下载书籍记录。
- 根据书籍记录恢复失败或未完成章节。
- 继续复用现有暂停、继续和删除整本下载接口。

管理页只调用 `DownloadService`，不直接修改 `DownloadStore` 记录。

## 书架删除联动

所有从书架移除单本书籍的流程统一执行以下顺序：

1. 调用 `DownloadService.deleteBookDownload(bookId)`，取消活动请求并删除最终文件、临时文件和记录。
2. 移除收藏记录。
3. 删除在线书缓存快照。
4. 对导入书：只有用户选择“删除本地文件”时删除原始导入文件；“仅移除书架”保留原始文件。

无论用户在导入书弹窗中选择“仅移除书架”还是“删除本地文件”，长期离线下载都必须删除。

下载清理失败不阻止书架记录移除，避免用户无法管理书架。页面在完成后提示“书籍已移除，部分下载文件清理失败”，并保留错误日志供排查。

批量“清空书架与历史”继续调用现有 `clearAllDownloads()`，行为与单书删除保持一致。

## 页面交互

- “我的”页面新增“下载管理”菜单项，使用下载图标和当前总占用空间摘要。
- 管理页操作按钮使用图标或图标加短文本，状态变化时保持列表尺寸稳定。
- 删除下载只删除长期离线文件，不移除书架。
- 管理页中的失败重试重新加入失败和未完成章节，不重复下载已完成且文件有效的章节。
- 所有用户可见文字放入资源文件。

## 验收标准

- 用户可以从“我的”进入下载管理页，集中查看所有下载记录和总占用空间。
- 下载状态变化能实时更新，暂停、继续、重试和删除操作可用。
- 点击下载书籍可以进入对应详情页。
- 任意单本书移出书架后，对应下载任务、`.part` 文件、最终文件和下载记录均被清理。
- 导入书选择“仅移除书架”时保留原始导入文件，但删除长期离线下载。
- 下载清理失败不会阻止移出书架，并给出明确提示。
- Debug HAP 构建成功。
