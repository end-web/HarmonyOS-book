# 下载进度与通知栏设计

## 目标

为长期离线下载增加实时字节进度，并使用 HarmonyOS 系统下载通知模板在通知栏显示单条汇总进度。
下载管理页和书籍详情页使用同一份实时进度数据。

## 进度数据流

`AudioDownloadTransport` 在流式接收数据时上报已写字节和响应 `Content-Length`。
`DownloadService` 在内存中保存活动章节进度，不把每次字节变化持久化，避免高频写入 JSON。

服务层按书籍计算：

- 已完成章节占固定权重。
- 当前活动章节在已知总字节时按字节比例计算。
- 总字节未知时显示不定进度状态，同时继续显示章节完成数。

进度事件节流到约 500 毫秒一次，完成、暂停、失败和删除不受节流限制。

## 页面展示

- 下载管理页每本书增加横向进度条和百分比。
- 未知总大小的活动任务使用不定进度条。
- 书籍详情页显示“下载中 已完成/总数 · 百分比”。
- 现有失败数、暂停、继续、重试和删除行为保持不变。

## 通知栏

新增 `DownloadNotificationService`，使用 `@kit.NotificationKit` 的 `notificationManager` 和系统
`downloadTemplate`：

- 第一次开始实际下载时请求通知授权。
- 始终使用同一个通知 ID，多本书同时下载时更新为汇总通知。
- 通知显示当前书名或“正在下载 N 本书”、总体百分比以及章节完成数。
- 暂停时更新为暂停状态。
- 全部完成后发布完成通知并设置自动清除时间。
- 删除全部任务或清空下载时取消通知。
- 用户拒绝通知权限或发布失败只记录日志，不影响下载。

通知仅用于展示，不改变当前进程内下载模型，也不承诺应用被系统强制终止后继续下载。

## 验收

- 下载管理页和详情页能看到随字节写入变化的进度。
- 通知栏显示一条系统下载进度通知，多本书下载不会产生多条通知。
- 暂停、继续、完成和清空会正确更新或取消通知。
- 未知 Content-Length 不会显示错误百分比。
- Debug HAP 构建成功。
