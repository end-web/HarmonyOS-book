# 听友预加载超时与播放失败提示设计

## 问题

听友播放地址依赖 guest token 和 `play_token`。网络波动、Token 失效或接口临时不可用时，
当前实现可能等待多个串行超时后返回空地址。后台预加载吞掉异常，主动播放只停止 loading 并写日志，
用户看不到失败原因。

## 设计

- 听友 `play_token` 请求失败时刷新 Token 并重试一次，不只处理 HTTP 401。
- 主动播放解析音频地址设置 15 秒总超时，超时或空地址均视为明确失败。
- `AudioService` 发布播放解析失败事件，播放页只对当前用户主动播放显示 Toast。
- 后台预加载失败记录日志和失败时间，不弹 Toast；同一章节 30 秒内不重复预加载。
- 成功解析或下载后清除失败冷却状态。
- 失败后保持当前书籍和章节，用户再次点击播放即可重新解析。

## 验收

- 听友临时 Token 或接口错误会自动重试一次。
- 主动播放最长等待 15 秒，失败后退出 loading 并显示可重试提示。
- 后台预加载失败不会打扰用户，也不会短时间连续轰炸接口。
- 接口恢复后用户可立即手动重试，冷却仅限制后台预加载。
- Debug HAP 构建成功。
