# 下载逻辑完整加固设计

## 目标

在保留现有 `DownloadService`、`DownloadStore`、`AudioDownloadTransport` 和
`DownloadPolicy` 模块边界的前提下，完善长期离线下载链路，使其能够可靠处理当前播放章节、
应用重启、网络中断、磁盘空间不足、异常响应、暂停、删除和失败重试。

## 范围

- 修复播放器把章节 `source` 改为本地文件后无法加入长期下载的问题。
- 调整启动恢复顺序，确保书源变量、登录信息和缓存环境初始化完成后再恢复任务。
- 增加磁盘空间预检、响应完整性校验和轻量音频文件头校验。
- 为失败原因建立稳定分类，并在页面显示可理解的错误信息。
- 补充策略单元测试和下载状态流测试；设备 API 相关行为通过设备测试验证。
- 不改用系统下载管理器，不增加数据库，不实现断点续传或 HLS 分片下载。

## 模块设计

### DownloadPolicy

`DownloadPolicy` 负责不依赖 HarmonyOS 设备 API 的纯判断逻辑：

- 从章节中选择稳定下载地址。优先使用 `originSourceValue`，其次使用网络类型的
  `source.value`。本地 `file` 章节只有在保留了 HTTP(S) 原始地址时才允许下载，
  `rawfile` 和没有网络原始地址的章节直接跳过。
- 识别 HLS、允许的音频 Content-Type 和常见音频文件签名。
- 将底层异常归类为 `network`、`storage`、`invalid_response`、`unsupported_hls`、
  `cancelled` 和 `unknown`。
- 继续提供任务代际和章节匹配判断。

纯策略集中后，可以在本地 Hypium 测试中覆盖绝大多数边界条件。

### AudioDownloadTransport

传输层继续使用 `requestInStream` 和 `.part` 临时文件：

1. 创建请求前检查下载目录是否可用，并查询文件系统剩余空间。
2. 收到响应头后，如果存在 `Content-Length`，要求剩余空间至少覆盖文件大小和安全余量；
   未提供长度时要求满足固定最低余量。
3. 仅接受成功的完整响应，不把重定向页、鉴权页或 HTML 错误页作为音频保存。
4. 写入完成后校验字节数、最小文件大小和文件头。Content-Type 缺失时允许通过文件头兜底；
   Content-Type 明确为非音频时直接失败。
5. 校验通过并 `fsync` 后，将 `.part` 原子移动到最终路径。
6. 取消、异常或校验失败时删除 `.part`，不覆盖已有可用最终文件。

本次不实现 Range 断点续传。失败任务从头重试，以避免服务端 Range 支持差异造成文件损坏。

### DownloadStore

持久化结构保留现有书籍和章节记录，给章节记录增加稳定错误码字段，同时保留用户可读的
`failureReason`。旧 JSON 没有错误码时按空值兼容读取。

状态规则：

- `pending`、`resolving`、`downloading` 表示活跃任务。
- `completed` 只允许对应可用的最终文件。
- `failed` 保留下载地址、最终路径和错误信息，便于重新入队。
- `deleted` 不参与活跃、成功或失败计数。
- 启动时将中断的 `resolving`、`downloading` 归一为 `pending`；只有原书籍状态为
  `queued` 或 `downloading` 时自动恢复，用户暂停的任务保持暂停。

读取记录后应校验 `completed` 文件是否仍存在且可用。文件缺失或损坏时将章节降级为
`failed`，避免 UI 显示已下载但播放器无法使用。

### DownloadService

服务层继续维护解析队列和文件队列，各自最多两个并发任务。

- 入队不再依赖当前 `source.type === 'url'`，而是调用策略层取得稳定 HTTP(S) 页面地址。
- 当前播放章节即使已被临时缓存改成 `file`，只要存在 `originSourceValue`，仍能进入长期下载。
- 单章、整本、后续二十章、增量下载和失败重试共享同一候选过滤逻辑。
- 暂停、单章删除、整本删除和全部清除继续推进任务代际并取消活动传输，旧回调不得更新记录。
- 自动恢复入口从 `init()` 中拆出，由应用完成书源相关初始化后显式调用，避免恢复任务读取到空的
  SourceVariableStore。
- 失败时保存错误码和可读原因；取消导致的旧任务不记录为失败。

### 页面反馈

书籍详情页继续显示总进度，并在存在失败章节时显示简短错误摘要。播放器章节列表中：

- 已完成显示完成图标。
- 下载中显示进度状态。
- 失败显示错误图标，长按可重新下载。
- 操作 Promise 必须处理异常，失败时显示具体原因或统一兜底提示。

用户可见文案放入资源文件，避免继续增加硬编码字符串。

## 启动顺序

应用启动顺序调整为：

1. 初始化 PreferenceService 和基础统计服务。
2. 初始化 DownloadStore，但不启动恢复队列。
3. 初始化 SourceVariableStore、CacheService 和其他书源运行环境。
4. 恢复播放器状态和必要服务。
5. 调用 DownloadService 恢复未中断完成的排队任务。

下载恢复失败不得阻断应用启动，只记录日志并保留任务为可手动重试状态。

## 错误处理

稳定错误码及默认文案：

| 错误码 | 默认文案 |
| --- | --- |
| `network` | 网络中断，请稍后重试 |
| `storage` | 存储空间不足或目录不可用 |
| `invalid_response` | 下载响应不是有效音频 |
| `unsupported_hls` | 暂不支持 HLS 音频离线下载 |
| `cancelled` | 下载已取消 |
| `unknown` | 下载失败，请重试 |

服务端 HTTP 状态码和底层异常保留在日志及 `failureReason` 中，但 UI 默认使用稳定文案，避免
直接展示难以理解的系统错误。

## 测试策略

本地单元测试覆盖：

- `file` 类型章节通过 HTTP(S) `originSourceValue` 正常入队。
- `rawfile`、无原始网络地址和非法协议被跳过。
- HLS、Content-Type、文件头和错误分类判断。
- 暂停、删除、清空后的旧任务代际失效。
- 删除章节匹配稳定页面地址，目录刷新后章节 ID 改变仍可识别记录。
- 失败记录重新入队，已完成且文件可用的记录不重复下载。
- 启动恢复只恢复原先处于排队或下载中的任务，不恢复暂停任务。

设备测试或人工验证覆盖：

- 下载中断网后记录为失败，恢复网络后可重试成功。
- 空间不足时不留下 `.part` 和错误的完成记录。
- 暂停、删除、清空期间活动 HTTP 请求被取消，之后不会复活文件或记录。
- 应用被终止并重启后，排队任务在书源环境就绪后恢复。
- 下载完成后断网播放，播放器优先使用长期下载文件。

## 验收标准

- 当前正在播放的网络章节可以成功加入长期下载，整本下载不会漏掉该章节。
- 依赖源变量或登录状态的下载任务重启后不会因初始化顺序错误而失败。
- 网络、空间和非法响应失败均不产生可播放的伪完成文件，并能明确提示用户。
- 暂停和删除操作完成后，不会出现旧任务回写状态或重新生成文件。
- 完成文件丢失或损坏后，状态能自动纠正并允许重新下载。
- 新增单元测试通过；具备 Hvigor 环境时项目可以正常构建。
